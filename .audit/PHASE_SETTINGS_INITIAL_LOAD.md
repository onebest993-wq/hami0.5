# تحميل مركز الإعدادات الأولي — 2026-08-12

## المشكلة

لقطة المستخدم: هيكل مستطيلات رمادية + عنوان فرعي «لوحة التحكم» — ليست واجهة الإعدادات الحقيقية. ذلك كان `SettingsScreenLoadingFallback` الوهمي أثناء انتظار مقطع المدخل (~836 ك.ب).

## ما أُنجز (بلا تغيير تصميم الشِل الحقيقي)

| تحسين | الأثر | ما لم نفعله |
|--------|--------|-------------|
| `SettingsInstantShell` = كروم حقيقي (عنوان، تبويبات، زر X 44px) | لا مستطيلات وهمية ولا «لوحة التحكم» | لم نُدخل 836 ك.ب إلى جذع اللوحة |
| أيقونات `homeStemIcons` لا `lucideIcons` | لا سحب lucide-react إلى LD | |
| `settingsInstantChrome.css` منفصل عن تخطيط البطاقات | جذع اللوحة يأخذ كروم الهيدر فقط | لم ننسخ CSS المحتوى إلى الـ stem |
| `HamiSettingsHost` يحمّل `HamiSettings` عبر `hamiSettingsLoader` | مقطع الـ Entry صار Host رفيع؛ المحتوى يُستبدل مكان القشرة | لم نُغيّر طلاء `paintSettingsInstantChrome` |
| MainView يستورد InstantShell مباشرة لا `LazyFallback` | لا سحب قشور المعاملات/الميدان مع الإعدادات | |

المسار الدافئ (بعد prefetch الإقلاع): Host يجد الوحدة في الكاش → الشِل الحقيقي من أول إطار.  
المسار البارد: كروم حقيقي فوراً → المحتوى يملأ اللوحة دون هيكل كاذب.

## التحقق

Vitest: **44 ملف / 146 اختبار — نجاح** (HamiSettings + فتح الإعدادات + Host + InstantShell + wave7m).

لم يُشغَّل E2E جهاز/Playwright في هذه الجولة.

## الحدود

1. أول فتح قبل اكتمال prefetch ما زال ينتظر مقطع `HamiSettings` — يظهر الكروم لا البطاقات. هذا انتظار صادق لا هيكل مزيف.
2. لا إثبات iOS / Capacitor ميداني لهذه الجولة.
3. `worldclassSettingsCloseHonesty` S2 (توقّع `isRealSignedIn`) فشل سابق خارج هذا العمل — الـ hook يستخدم `hasLocalAppSession`.
4. لم نُطابق هيكل بطاقات المنظر أثناء الانتظار (يمنع CLS كاذب).
