# تقرير إغلاق — إعادة بناء الإحضار الجبري من الصفر

تاريخ: 2026-08-04

## ما أُنجز

1. **محرك دورة حياة واحد** — `forcedBringInvestigationLifecycle.ts`
   - طلب إحضار → موافقة → حضور | تجاهل | متخفي
   - متخفي → إخفاء الإحضار + إظهار مفاتحة التحقيق
   - مفاتحة → موافقة → حضور (إعادة كاملة) | إصدار مذكرة قبض → تم تأمين إحضار المدين
2. **إزالة التنازل بالكامل** من UI الإحضار/المفاتحة (كان خطأ سابقاً ولم يُطلب).
3. **تنظيف** `PersonalCoerciveFollowupPanel` — ربط النتائج بالمحرك، إصلاح شرط إرسال المفاتحة بعد متخفي.
4. **توحيد نتيجة الإحضار بعد موافقة المنفذ** في مسار تكليف الموظف (حضور / تجاهل / متخفي) عبر نفس patch.
5. **اختبارات**: 40 اختباراً لمحرك/utils + بنية اللوحة والطعون.

## الحدود

- مسار **تكليف الموظف** ما زال يبدأ بمفاتحة ثم مذكرة ثم إحضار (ترتيب قانوني مختلف) — لكن **نتيجة الإحضار بعد موافقة المنفذ** وحّدت لتطابق الدورة.
- handlers قديمة في summons/earner لم تُحذف بالكامل (خارج نطاق «بطاقة الإحضار» في محضر المتابعة).
- لم يُختبر يدوياً على ملف المستخدم في المتصفح في هذه الجلسة.

## جاهز للانتقال؟

**نعم لمسار الإحضار الجبري في محضر المتابعة** — بشرط تحقق يدوي سريع:

1. طلب إحضار (أو بقرار المنفذ) → موافقة → 3 خيارات.
2. حضور/تجاهل → تعود بطاقة الطلب.
3. متخفي → تختفي بطاقة الإحضار وتظهر المفاتحة (قيد البت/إرسال).
4. موافقة المفاتحة → حضور أو مذكرة → ثم «تم تأمين إحضار المدين» فقط.
5. لا تظهر نافذة «تنازل عن مفاتحة التحقيق» عند الضغط على الإحضار الجبري.

## المصداقية — ما لم يُنفَّذ

- لم نعد كتابة ملف اللوحة بالكامل سطراً بسطر (3900+ سطر) — أُعيد بناء **دورة الإحضار/المفاتحة** كمحرك + تنظيف المقاطع ذات الصلة.
- لم نوحّد كل handlers الـ summons القديمة في نفس الجلسة.
