## 6. دورك (بالترتيب)

لا تلصق أسراراً في الدردشة. انسخ القيم من `.env.production.local` إلى لوحات التحكم فقط.

### أ) أسرار Edge في Supabase
1. افتح مشروع **hami 0.5**.
2. Edge Functions → Secrets.
3. تأكد من وجود: `WIFE_DISABLE_EDGE_KV_PROXY=true` و`WIFE_DISABLE_EDGE_COMMS_DISPATCHER=true`.
4. `ADMIN_ACCESS_KEY` إن أردت تشخيص Edge (بدونها التشخيص 503 — مقبول).

### ب) متغيرات Vercel (Production + Preview إن لزم)
انسخ من `.env.production.local` / `.env` الأسماء التالية **بدون عرض القيم هنا**:

- `SUPABASE_URL` ، `SUPABASE_ANON_KEY` ، `SUPABASE_SERVICE_ROLE_KEY`
- `VITE_SUPABASE_URL` ، `VITE_SUPABASE_ANON_KEY`
- `VITE_BFF_AUTH=true`
- `VITE_SHELL_AUTH_OPEN` غير `true` في الإنتاج
- `WIFE_REDIS_REST_URL` ، `WIFE_REDIS_REST_TOKEN`
- `WIFE_DISABLE_EDGE_KV_PROXY=true`
- `SITE_URL` و`PASSWORD_RESET_ALLOWED_ORIGINS` = رابط موقعك
- `VITE_ENABLE_CLOUD_SYNC=true` **فقط** إذا أردت أن *يُسمح* بمزامنة العمل عندما يفعّلها المحامي في الإعدادات. اتركه مطفأ إن أردت العمل محلياً دائماً.

ثم **Redeploy**.

### ج) Redis حي من جهازك (PowerShell في جذر المشروع)

```powershell
npm run doctor:wife-redis
npm run gate:wife-prod-live:only
```

المتوقع: Redis يصل، و`gate` بلا حاجز مع `--live`.

إن فشل Redis: Upstash → REST API → حدّث المفتاحين في الملف المحلي **وفي Vercel** ثم أعد النشر.

### د) دخان يدوي بعد النشر
1. افتح رابط Vercel — شاشة دخول (ليس الشِل المفتوح).
2. سجّل دخولاً حقيقياً.
3. منتدى: منشور واحد.
4. ملف مهني: صورة/تعديل بسيط.
5. دعاوى/تنفيذ/تقويم **والمزامنة مطفأة في الإعدادات:** يجب أن تعمل بلا أخطاء شبكة WIFE.
6. إن فعّلت المزامنة عمداً: حفظ إضبارة ثم إعادة تحميل.

### هـ) Playwright (اختياري بعد خادم معاينة)

```powershell
npm run test:e2e:wife
```

يحتاج `npm run dev` أو معاينة Vercel حسب إعداد e2e عندكم.
