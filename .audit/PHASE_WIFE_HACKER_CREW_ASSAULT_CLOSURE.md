## 1. ما أُنجز

| المجال | السلوك |
|--------|--------|
| عزل `user:<id>:` | بادئة المستخدم العريضة تُحسب عملاً محلياً؛ `user:<id>:profile` يبقى على الشبكة |
| مسح KV | `kvGetByPrefix` / `kvKeysByPrefix` / `kvDelByPrefix` بمدى ترتيب لا LIKE — `%` و`_` لا يوسّعان المسح |
| متابعة | `getFollowing` ببادئة `follow:<id>:` المملوكة؛ مسح `follow:` العام مرفوض (كان IDOR نظرياً و403 عملياً) |
| طاقم مهاجمين | `wifeHackerCrewAssault.test.ts` — فيضان غير موقَّع متزامن + KV + عزل + تشفير + خفة |

## 3. ثغرات وُجدت وأُغلقت

| الشدة | الاكتشاف | الإصلاح |
|-------|----------|---------|
| متوسطة | `getByPrefix('user:<id>:')` لم يُصنَّف عملاً محلياً فيُمكن سحب القضايا مع الملف المهني والمزامنة مطفأة | `isWorkLocalKvMaterial` يعتبر كل `user:` عملاً إلا `…:profile` |
| متوسطة | `.like(prefix%)` يجعل `_` و`%` أحرفاً عامّة (`lawyer_files` يحتوي `_`) | مدى `gte`/`lt` + `startsWith` |
| منخفضة | `getByPrefix('follow:')` ي.dump كل المتابعات إن سُمح به | رفض البادئة العامّة؛ قراءة المتابَعين بـ `follow:<أنا>:` |

## 4. الخفة (مُقاس بالاختبار لا بجهاز)

- الحارس لا يوقّع `/logo.svg` ولا أصول طرف ثالث.
- قشرة الإقلاع لا تُسخّن `hami:lawyerdb` ولا المستعجل ولا سجل المعاملات.
- CSRF ليس `void` عند كل إقلاع؛ GET آمن بلا رأس CSRF.
- `CryptoService` إعادة التهيئة بنفس الغلاف **< 50ms** (ذاكرة).
- محرّك المزامنة لا يفحص الجلسة إذا مزامنة العمل مطفأة.

HMAC نفسه رخيص؛ التكلفة المتبقية هي BFF `wife-sign` **عندما** يُستدعى `/api` فعلاً، وPBKDF2 عند البرد.
