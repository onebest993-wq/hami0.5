# PHASE — عزل WIFE عن أقسام العمل المحلية

**التاريخ:** 2026-08-29  
**النطاق:** القلب (WIFE + التشفير عند الراحة) لا يتدخل في الدعاوى/التنفيذ/التقويم/المعاملات/المستودع ما دامت مزامنة العمل مطفأة.  
**لا تغيير بصري.**

---

## 1. ما أُنجز (ملموس)

| المجال | السلوك |
|--------|--------|
| بوابة عمل واحدة | `isLawyerWorkCloudLive()` = ليس عزل محلي + `cloudSync` + `VITE_ENABLE_CLOUD_SYNC` |
| KV | `lawyerCloudKv` يرفض مفاتيح العمل المحلية قبل `/api/kv-proxy`؛ `profile:` و`follow:` تبقى على الشبكة |
| سلال حيّة | `isLiveCloudSyncBucketEnabled` يضم البيئة — الإعدادات وحدها لا تفتح `/api` |
| محرّك المزامنة | `canRunCloudSync` لا يفحص الجلسة إذا المزامنة مطفأة؛ كل سلة تُتخطى وحدها (`files` = دعاوى كما في اللوحة) |
| حذف محلي | حذف دعوى/تنفيذ نهائي لا يستدعي `/api/lawsuit-files` أو `/api/execution-files` بلا سلة حيّة |
| LawyerDB | قضايا/ملاحظات/مواعيد محلية بلا رمي KV؛ الملف المهني يبقى KV |
| مستعجل / مستودع / مخزن / تقويم / معاملات | قصر شبكة خلف البوابة |
| CSRF | ليس عند كل إقلاع؛ `DELETE` فقط إن وُجدت جلسة خادم |
| عند الراحة | `hami:lawyerdb:` و`hami:urgentActions:v1:` و`hami:transactions:` تُشفَّر |

## 2. التقييم (واقعي)

| البُعد | درجة | ملاحظة |
|--------|------|--------|
| أداء | 8/10 | فتح الأقسام المحلية بلا HMAC/CSRF/kv-proxy. تكلفة البروتوكول باقية **عندما** يُستدعى `/api` فعلاً (BFF `wife-sign`، PBKDF2 بارد). |
| نظافة | 8/10 | لا رمي KV كتحكم بالتدفق في LawyerDB. عميل KV مكرّر في المستعجل ما زال موجوداً ومبوّباً. |
| أمان | 8/10 | عزل قرار الشبكة + تشفير مفاتيح العمل. ليست مراجعة اختراق حيّة ولا جهاز Capacitor. |
| جودة كود | 8/10 | بوابة واحدة + سلال حيّة + اختبارات عزل. لا أزرار مزامنة جديدة (ممنوع بلا إذن UI). |
| موبايل | 7/10 | العزل يقلّل شبكة/بطارية في الوضع المحلي. لم يُقاس على جهاز. |
| صدق | 9/10 | الحدود أدناه معلنة. |

## 3. التحقق

دفعات vitest (ليس `vitest run` لكل المستودع):

- عزل السلال / LawyerDB / CSRF / مستودع / صدق الأقسام المحلية: ناجح
- محرّك المزامنة + شواهد الحذف + `useCloudSync` + حذف الدعاوى: ناجح (79 اختباراً عبر دفعتين)
- مفاتيح التشفير + `runCloudSyncAllNow` + صدق أمان المعاملات (بعد تحديث اسم مسار المحو): ناجح

لم يُشغَّل: حملة WIFE E2E كاملة، بناء الإنتاج، جهاز حقيقي.

## 4. الحدود (ما لم يُنفَّذ — ولماذا)

| الحد | السبب |
|------|--------|
| تخزين توقيع WIFE | nonce لمرة واحدة — التخزين يكسر البروتوكول |
| دمج HMAC عميل/خادم | طبقتان متعمّدتان |
| بوابة `LawyerStorage.uploadSmartFile` لكل الفئات | المنتدى ورفع الملف المهني يشاركان المسار؛ القصر عند مستودع العمل فقط |
| أزرار مزامنة لكل قسم (تقويم/معاملات/مخزن) | ممنوع بلا إذن UI؛ تتبع `cloudSync` الرئيسي |
| إغلاق `profile:` KV | الملف المهني/البوابة حسابية مسموحة على الشبكة |
| عميل KV داخل `urgent-actions-db` | مبوّب بـ `VITE_URGENT_CLOUD_SYNC` + بوابة العمل؛ توحيد العميل ليس حاجة عزل |
| قياس Capacitor حي | خارج هذه الجلسة |

---

## 5. الموقع

**جاهز للانتقال: نعم** — ضمن حدود القدرة أعلاه. القلب معزول عن أقسام العمل المحلية ما دامت المزامنة مطفأة. ما يبقى هو تكلفة WIFE/التشفير **عند** شبكة مشروعة، لا تدخل صامت في الدعاوى أو التقويم أو المعاملات.
