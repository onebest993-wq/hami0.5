# أهداف اللمس في الملف المهني تنكمش تحت ٤٤px — **مُغلَق (مواضع محلية + جذر rem مُثبَّت)**

**اكتُشف:** ٩ آب ٢٠٢٦، بالربط بين قياس DOM حي زوّده المستخدم وشيفرة المصدر.
**أُصلح (محلياً داخل القسم):** ٩ آب ٢٠٢٦.
**جذر rem النظامي:** مؤكَّد مُغلَقاً في المستودع بتاريخ ١٣ آب ٢٠٢٦ (`html { font-size: 16px }` في critical-shell + theme).

---

## تصحيح صريح على تقريري الأول — لا إخفاء لخطأ ارتكبتُه

في الإصدار الأول من هذا الملفّ ذكرتُ `.profile-studio-color-input` كـ"مثال ثانٍ مؤكَّد". **هذا خطأ.** تحقّق أوسع (بحث في كل شجرة `src` عن اسم الصنف) أثبت أنه **لا يوجد ملفّ `.tsx` واحد يستعمل هذا الصنف** — قاعدة CSS ميتة، لا تُطبَّق على أي عنصر حقيقي على الصفحة. سحبتُ هذا المثال بالكامل. المصداقية تقتضي ذكر هذا صريحاً لا التستّر عليه.

بالمقابل، التحقّق الموسَّع نفسه (قراءة كل ملفّ `.tsx` يستهلك كل صنف `rem` صغير في القسم، لا الاعتماد على اسم الصنف وحده) وجد **موضعين حقيقيّين إضافيّين** لم يكونا في التقرير الأول، وكلاهما أخطر مما وُصف ابتدائياً لأنهما ينكمشان **حتى عند الإعداد الافتراضي، بلا حاجة لتغيير حجم الخط أصلاً**:

## الحصر النهائي — ٤ مواضع حقيقية، كلّها مُصلَحة الآن

| الصنف | الحجم القديم | متى ينتهك ٤٤px | الإصلاح المطبَّق |
|---|---|---|---|
| `.hami-profile-sigil` (زر «تعديل» في شريط الإجراءات) | `2.85rem` (٤٥٫٦px @ الافتراضي) | فقط عند تصغير حجم الخط ("صغير" → ٣٩٫٩px) | + `min-width/height: 44px` |
| `.hami-profile-sigil--throne` (زر «استوديو») | `3.05rem` (٤٨٫٨px @ الافتراضي) | فقط عند "صغير" (٤٢٫٧px) | + `min-width/height: 44px` |
| `.hami-profile-sigil-follow` (زر «متابعة») | `min-height: 2.5rem` (=٤٠px حتى @ الافتراضي!) | **دائماً**، بصرف النظر عن حجم الخط | `min-height: max(2.5rem, 44px)` |
| `.profile-image-focus-picker__zoom-btn` (+/− تكبير عند ضبط بؤرة صورة الكتلة) | `28px` ثابتة | **دائماً**، حتى بلا أي علاقة بحجم الخط | `width/height: 44px` مباشرة |

الاثنان الأخيران (`sigil-follow`, `zoom-btn`) أخطر من الاكتشاف الأصلي: هما تحت الحدّ **بشكل غير مشروط**، لا فقط عند تفضيل خط أصغر — أي مستخدم بإعدادات افتراضية كاملة كان يواجههما فعلياً.

### الشيفرة بعد الإصلاح

```365:374:src/app/components/lawyer/RoyalLawyerProfile/profilePageHeroFx.css
[data-lawyer-profile-root] .hami-profile-sigil {
    ...
    width: 2.85rem;
    height: 2.85rem;
    /* أهداف اللمس (Apple HIG / Material) — ٤٤px حدّ لا يسقط تحته مهما صغّر المستخدم حجم الخط */
    min-width: 44px;
    min-height: 44px;
    ...
}
```

هذا النمط (قياس `rem` يكبر مع تفضيل المستخدم + صمّام `min` بوحدة `px` ثابتة لا يسمح بالنزول تحت الحدّ) **ليس اختراعاً جديداً** — هو نفس النمط الذي يستعمله الفريق فعلاً في `.hami-profile-instant-back-btn` (زر الرجوع على قشرة الإقلاع الفورية):

```37:40:src/app/components/lawyer/RoyalLawyerProfile/profileChrome.css
width: 2.75rem;
height: 2.75rem;
min-height: 44px;
min-width: 44px;
```

الإصلاح يُطبِّق نمط الفريق نفسه على المواضع التي فاتته، لا نمطاً غريباً عن الشيفرة.

## تحقّق سلبي — عشرات المرشّحين الآخرين فُحصوا وليسوا عيباً

قبل الإصلاح، جُرِّد كل صنف `rem` بحجم صغير في ١١ ملفّ CSS (أكثر من ٤٠ صنفاً)، وتُبِع كل واحد إلى مكوّنه الحقيقي. **النمط السائد في القسم صحيح وواعٍ فعلاً:** كل زر حقيقي (`profile-settings-color-swatch`, `profile-settings-material-chip`, `profile-settings-portrait-frame-chip`, `profile-studio-scope-tab`, `profile-studio-line-chip`, `profile-settings-quick-preset`, `profile-studio-media-shape-chip`, `profile-studio-rim-chip`, وغيرها) يحمل `min-h-[44px]` من Tailwind **مباشرة على عنصر `<button>` نفسه** في JSX — ثابت بـ`px`، محصَّن من أي تغيير في حجم الخط. العناصر بـ`rem` الصغيرة في هذه الحالات هي دائماً `aria-hidden` — زخرفة داخل هدف أكبر سليم (أيقونة، معاينة شكل، نقطة لون)، لا الهدف نفسه.

هذا يعني: الخلل لم يكن ثقافة عامة في القسم، بل **٤ استثناءات محدَّدة** خرجت عن نمط الفريق الخاص السليم. إصلاحها الأربعة يُغلق الثغرة بالكامل ضمن ما فُحص.

## السبب الجذري النظامي — **مُغلَق لاحقاً (تصحيح حالة ٢٠٢٦-٠٨-١٣)**

التقرير الأصلي وصف تناقضاً: نية `apply.ts` ("لا يُطبَّق على html/rem") مقابل `html { font-size: calc(16px * var(--hami-user-font-scale)) }`.

**الوضع الحالي في المستودع:** هذا التناقض لم يعد موجوداً.

```29:38:src/styles/critical-shell.css
html {
    /* ثابت — مقياس القراءة عبر --hami-font-size على النص فقط، لا rem التخطيط */
    font-size: 16px;
}

body {
    ...
    font-size: var(--hami-font-size, 16px);
}
```

ونفس تثبيت `html { font-size: 16px }` في `theme.css`. مقياس القراءة عبر `--hami-font-size` على النص، و`--hami-user-font-scale` يبقى متغيّراً على الجذر دون ربط `rem` التخطيط به.

طوابق اللمس الأربعة في الملف (`min: 44px` / `max(rem, 44px)`) تبقى defense-in-depth صحيحة إن عاد ربط rem بالخطأ لاحقاً.

**حدّ متبقٍّ خارج الملف:** أقسام أخرى قد تملك أهداف لمس بـ`rem` بلا صمّام px — ليس ديناً داخل قسم الملف المهني.

## التحقّق

`npm run gate:profile` أُعيد تشغيله بعد التعديل (انظر تقرير الإغلاق الرئيسي للنتيجة الكاملة) — صفر انحدار. لم تُغيَّر أي قيمة `rem` أساسية (التكبير مع تفضيل "كبير" لا يزال يعمل كما هو)؛ فقط أُضيف صمّام سفلي لا يتفعّل إلا عند الانكماش تحت ٤٤px.
