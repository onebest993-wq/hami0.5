# PHASE — إغلاق الثغرات المهنية (فهرس المتابعة + مستودع المالك + HQ بلا LIKE)

**التاريخ:** 2026-08-29  
**النطاق:** منطق KV/WIFE فقط. لا تغيير بصري. طلب المستخدم: عمل كامل بلا حلول رخيصة.

---

## 1. ما أُنجز

| المجال | السلوك |
|--------|--------|
| فهرس المتابعين | `FollowDB` يكتب `follow:<follower>:<following>` و`followers:<following>:<follower>`؛ `getFollowers` يقرأ البادئة العكسية. فشل العكسي يلغي الأمامي. |
| ملكية KV | `followers:` تُفسَّر قبل `follow:` حتى لا يختلط النص. الكتابة على الفهرس العكسي للمتابِع فقط — لا زرع متابعين على الضحية. |
| المستودع | مفاتيح `repository:docs:<authorId>:<docId>`؛ القراءة/الكتابة للمالك. المسح العام `repository:docs:` = 403. الدمج السحابي ببادئة المستخدم الحي. |
| المستعجل | عميل KV المزدوج أُزيل؛ السحابة عبر `lawyerCloudKv` خلف `VITE_URGENT_CLOUD_SYNC` + مزامنة العمل. |
| مقر القيادة | مسح البادئة بمدى ترتيب لا LIKE (`applyKvKeyPrefixRange`). |
| مسح الحساب | هجرة `wipe_user_application_data` تحذف الشكل الجديد + الفهرس العكسي. **مطبّقة على hami 0.5** (`20260829120232`). |
| Edge | `npm run sync:kv-ownership` |

## 3. ما كان «رخيصاً» وأُغلق

| الشدة | السابق | الآن |
|-------|--------|------|
| عالية | `getFollowers` يعيد `[]` | فهرس عكسي حقيقي + اختبارات اتجاهين والتراجع |
| عالية | أي مصادق يقرأ كل `repository:docs:*` بينما الكتابة 403 | ملكية كالمخزن؛ الكتابة تعمل للمالك |
| متوسطة | عميل kv-proxy مكرر في المستعجل | `lawyerCloudKv` مع بوابة البيئة |
| متوسطة | HQ `.like('key', prefix%)` | مدى `gte`/`lt` + ترتيب مستقر للصفحات |
| منخفضة | `followers:`.startsWith(`follow:`) | تحليل `followers:` أولاً |

## 5. الحدود

| الحد | السبب |
|------|--------|
| مفاتيح `repository:docs:<id>` القديمة | فشل مغلق عن عمد. لا واجهة ترحيل، ولا قراءة عامة. |
| هجرة المسح SQL | مطبّقة على hami 0.5. ملف محلي: `supabase/migrations/20260829120232_kv_owner_scoped_repository_followers.sql`. |
| ترحيل مفاتيح المستودع | مطبّق (`20260829120234`). KV الحالي بلا مفاتيح `repository:docs:<id>` غير مقيَّدة. |
| الكتابة المزدوجة للمتابعة | ليست معاملة Postgres؛ التراجع يحذف الأمامي إن فشل العكسي. المسار الأساسي للمنتدى يبقى `ForumFollowRepository`. |
| مسح الحساب SQL لبقية البادئات | ما زال `LIKE` بمعرّف UUID عبر `service_role` — نموذج تهديد مختلف عن kv-proxy. |
| تخزين توقيع WIFE / دمج HMAC | مرفوض تصميمياً (nonce لمرة). |
| E2E / Redis / Capacitor | غير مُشغَّلة هنا. |
