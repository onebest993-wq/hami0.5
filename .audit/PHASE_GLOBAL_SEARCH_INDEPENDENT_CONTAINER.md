# البحث الشامل — حاوية مستقلة + جاهزية Android

تاريخ: 2026-08-13  
نطاق: `header-search-trigger` / Global Search Overlay  
أسلوب: نفس معيار الإعدادات/الإشعارات (html attr + تجميد الرئيسية + طبقة معتمة)

---

## ما أُنجز

1. **حاوية مستقلة** — لم تعد الرئيسية تُرسم تحت البحث.
   - `globalSearchOverlay.css` + `lawyerHomeFx-critical.css`: تجميد `[data-hami-dashboard-underlay]` بـ `content-visibility: hidden`، إخفاء `.hami-lawyer-header`، إخفاء الطبقة عند غياب `data-hami-global-search-open`.
   - خلفية الطبقة/الستارة/الـ backdrop: `#0a0f1c` معتمة (لا تسريب بطاقات المنزل).

2. **الكيبورد لم يعد يكشف الرئيسية** — السبب الحقيقي لـ «النتائج أزرار».
   - سابقاً `resolveGlobalSearchLayerStyle` يضغط الطبقة بـ `bottom: kb` فوق IME → بطاقات دعاوي/تنفيذ/مهام/معاملات تظهر في الفجوة.
   - الآن الطبقة `inset: 0` دائماً؛ الورقة فقط تُرفع بـ `marginBottom`.

3. **a11y** — `underlayInert` يشمل `showGlobalSearch`.

4. **عقد G9 محدّث** — البحث حاوية مستقلة لا «رئيسية مرسومة تحتها».

5. **الفتح/الإغلاق الفوري** بقي: reveal → snap html → flushSync؛ الإغلاق `executeOverlaySnapClose`.  
   `activateOnPointerDown={false}` متعمّد (سباق flushSync + IME على Android).

## الحدود (صريح)

- **الجهاز:** لا إثبات على WebView حتى `npm run cap:sync:android` + Studio Run.
- **pointerdown:** الإعدادات تفتح عند الضغط؛ البحث يفتح عند click بعد prefetch على pointerdown — حماية IME. الطبقة الدافئة + html attr تجعل الإطار الأول فورياً إن كان Host مركّباً.
- **شكل صف النتيجة (`ResultRow`):** لم يُغيَّر (قاعدة التصميم). «الأزرار» في اللقطات كانت بطاقات المنزل المتسرّبة، لا قائمة البحث.
- **اللوحي:** الخلفية حول البطاقة صارت معتمة بالكامل (حاوية مستقلة) بدل تعتيم المنزل.
