# عطل مُصلَح: حارس المسح كان معطّلاً على المفاتيح المشفَّرة وحدها

**اكتُشف وأُصلح:** ٩ آب ٢٠٢٦، أثناء مراجعة طبقة التخزين وترقيم المخطَّط.
**الخطورة:** فقدان دائم وصامت لبيانات المحامي.
**الحالة:** مُصلَح ومُغطّى باختبارات تفشل بدون الإصلاح.

---

## ما كان يحدث

`shouldRejectDossierWipe` هو دفاع التطبيق الأساسي عن بيانات الإضابير: يمنع
استبدال قائمة غير فارغة بقائمة فارغة. يعمل بعدّ عناصر JSON في الموجود وفي
الوارد، ويرفض إن كان الوارد صفراً والموجود أكثر.

و`SecureStoreService.setItem` كان يمرّر إليه **النصّ المخزَّن كما هو**:

```ts
const existing = webFallbackStore.get(key) ?? (await this.webDbGetItem(key));
if (existing && this.shouldRejectEmptyOverwrite(key, value, existing)) { … }
```

والمخزَّن للمفاتيح الحساسة نصّ مشفَّر يبدأ بـ`hami_enc_v2:`. فـ`JSON.parse`
يرمي، و`countProtectedItems` يبتلع الاستثناء ويعيد `0`:

```ts
} catch {
    return 0;   // ← «لا أستطيع القراءة» تُقرأ «لا يوجد شيء»
}
```

فشرط الرفض `incomingCount === 0 && existingCount > 0` لا يتحقّق أبداً، ويُسمح
بكتابة `[]` فوق البيانات.

## المفاتيح التي كانت مكشوفة

كلّ مفتاح **محميّ ومشفَّر** معاً — أي قلب بيانات المحامي بالضبط:

| المفتاح | المحتوى |
|---|---|
| `lawyer_files` | الدعاوى |
| `executionFiles` | فهرس إضابير التنفيذ |
| `lawyer_notes` | الملاحظات |
| `lawyer_settings` | الإعدادات |
| `lawsuit_files` / `execution_files` / `lawyer_execution_files` | مفاتيح قديمة مرآة |
| `hami:criminal:case:*` | شظايا القضايا الجنائية |

المفاتيح غير المشفَّرة (`hami:calendar:events:v1`، `hami:community:posts:v1`،
`hami:smartvault:docs:v1`، `hami:criminal:store`) كانت محميّة فعلاً — ولهذا لم
يكشف أحدٌ العطل: الاختبارات تُمرّر نصّاً صريحاً، فتمرّ خضراء دائماً بينما
المسار الحقيقي يُمرّر نصّاً مشفَّراً.

## العطل الثاني: التالف يُقرأ فراغاً

نفس السطر (`catch { return 0 }`) يُنتج سلسلة ضياع مستقلّة عن التشفير:

1. حمولة مخزَّنة تتلف (كتابة مبتورة، امتلاء حصّة، انقطاع أثناء الحفظ).
2. القارئ يفشل في `JSON.parse` فيعيد `null` — والواجهة تفتح خالية.
3. أول حفظة تلقائية تكتب `[]`.
4. الحارس يعدّ الموجود «صفراً» لأنه لم يستطع تحليله، فيأذن.
5. آخر نسخة كانت قابلة للإنقاذ تُمحى.

وكانت النسخة الثانية من حارس بلوب الإضبارة تحمل الشكل نفسه صراحةً:

```ts
if (!existing || !incoming) return false;   // موجود لا يُقرأ ⇒ اسمح
```

## الإصلاح

1. **`readProtectedItemCount`** يعيد `null` حين يتعذّر الفهم، و`0` حين لا توجد
   عناصر فعلاً. `countProtectedItems` بقي على حاله فوقه لمن لا يحتاج التمييز.
2. **`shouldRejectDossierWipe`**: الموجود غير المقروء + وارد يُفرِّغ ⇒ **رفض**.
   وارد فيه عناصر ⇒ مرور، فالاستعادة فوق التالف لا تُمنع.
3. **`SecureStoreService.setItem`** يفكّ التشفير قبل استدعاء الحارس. وحين يفشل
   الفكّ يمرّر النصّ المشفَّر عمداً ليقع في فرع «غير مقروء» فيُرفض التفريغ.
4. **`setItemSync`**: لا فكّ تشفير في مسار متزامن. حين تكون الذاكرة باردة
   والحمولة مُفرِّغة، تُحوَّل الكتابة إلى المسار غير المتزامن ليقرأ الأصل
   ويحكم — لا رفض أعمى يُضيّع حذفاً قصده المستخدم، ولا سماح أعمى.
5. **`shouldRejectExecutionDossierBlobWipe`**: نفس المبدأ، وحُذفت النسخة
   المكرّرة حرفاً بحرف في `executionDossierBlobPersistence.ts` لصالح استدعاء
   الأصل — كان إصلاح إحداهما يترك الأخرى مكشوفة بلا إشارة.

## البرهان

`src/app/services/__tests__/secureStoreEncryptedWipeGuard.test.ts` يكتب قيمة
حقيقية عبر `setItem` (فتُشفَّر فعلاً) ثم يكتب `[]` فوقها ويقرأ.

بدون الإصلاح: `expected [] to have a length of 2` — ثلاثة مفاتيح تُمحى.
مع الإصلاح: البيانات باقية، والتحديث الحقيقي والكتابة الأولى تمرّان.

وكذلك `dossierWipeGuardUnreadable.test.ts` للتالف والمشفَّر على مستوى الحارس.

## كسر الصمت

المنع وحده لم يكن كافياً: المحامي يفتح فيرى شاشة خالية، ولا يعلم أن أضابيره ما
تزال على الجهاز، ولا يظهر شيء في أي لوحة. `corruptStorageSignal.ts` يُبلِغ
مرّة واحدة لكل مفتاح في العمر، **من القراءة كما من الكتابة** — لأن من يفتح ولا
يحفظ لا يمرّ بمسار الكتابة أبداً. ويصمت عن المفاتيح غير المحمية حتى لا يُدرَّب
أحد على تجاهل البلاغ.

## ما لا يغطّيه هذا الإصلاح

- **اختلاف الشكل** (JSON سليم بحقول مختلفة): يمرّ، والتطبيع قد يُسقِط حقولاً
  بصمت. هذا نطاق ترقيم المخطَّط لا نطاق الحارس — وقد وُضعت مرساته الآن في
  `src/app/services/storageSchema/`.
- **لا واجهة للمستخدم**: البلاغ يذهب إلى Sentry لا إلى المحامي. لا شاشة تقول
  «بياناتك موجودة لكن تعذّرت قراءتها». هذا نقص مُعلَن لا مُنكَر.
- **لا استعادة تلقائية** من النسخ الاحتياطية في IndexedDB عند اكتشاف التلف؛
  المسار موجود (`protectedBackupService`) لكنه غير مربوط بهذه الإشارة بعد.
