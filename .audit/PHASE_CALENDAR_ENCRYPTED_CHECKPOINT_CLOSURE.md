# إغلاق مرحلة — التقويم داخل نقطة الحفظ المشفّرة

**التاريخ:** ٣٠ آب ٢٠٢٦  
**النطاق:** إدخال المواعيد في «مزامنة كل شيء» دون KV ودون `/api/calendar`.  
**لا تغيير بصري.**

---

## الحكم

الحد السابق كان صحيحاً: مفاتيح `calendar:` على KV تكشف وجود جلسات حتى لو القيمة مختومة، وعناوين الجلسات تحمل أسماء. الحل المهني ليس فتح KV، بل ركوب التقويم داخل **نفس ciphertext** نقطة العمل (`POST /api/work-checkpoints`) بعد AES المحلي. الخادم يخزّن `encrypted_data` + توقيع فقط — لا عمود تقويم ولا مفتاح موعد.

هذا «حزمة مستقلة» عن KV، لا مسار HTTP ثانٍ. مسار ثانٍ كان سيضاعف سطح WIFE دون فائدة: الخادم لا يفك التشفير في الحالتين.

حفظ الموعد اليومي ما زال جهاز-فقط. الشبكة تُوقَّع بـ WIFE عندما تُدفع نقطة العمل (`cloudSync` حي) — حتى إن أُطفئت سلال الدعاوى/التنفيذ/الملاحظات، لأن التقويم لا يملك KV.

## ما أُنجز

| المجال | السلوك |
|--------|--------|
| جمع | `collectCalendarCheckpointSlice` من IndexedDB المحلي + شواهد الحذف. لا `lawyerCloudKv` |
| استبعاد المحذوف | عنوان الموعد المشهود حذفه لا يدخل النص قبل AES |
| مالك الشريحة | الجمع والتطبيق يصفّيان على `resolveLiveAuthUserIdForStorage` — مواعيد/شواهد مستخدم آخر لا تُرفع ولا تُكتب |
| دفع | حقول `calendar` / `calendarTombstones` داخل حمولة v1 القائمة |
| فيض | إن تجاوزت الشريحة 1.3MB بايت أو ciphertext 1.8M تُسقط المواعيد بعلم `calendarOmittedForBudget` وتُحفظ الإضابير إن أمكن |
| استعادة التقويم بعد فيض | GET يعيد آخر `KEEP_LATEST` صفوف **زائد** أحدث صف `keep_anchor` ولو كان أقدم من النافذة. الدمج بعد الفك يأخذ التقويم من الحزمة المكتملة |
| keep_anchor | العميل يرسله خارج ciphertext عندما الحزمة مكتملة. الخادم أعمى ويُبقي أحدث صف معلَّم. أربع دفعات فيض في roundtrip لا تمسح التقويم. تخزين أسوأ حالة: 4 × 1.8MB لا ن صفوف بلا حد |
| استعادة الكتابة | دمج بالمعرّف (`saveEventsBatch`) ثم شواهد الحذف؛ كاش العرض يُصفَّر ويُبلَّغ السطح |
| KV / BFF | `isCalendarNeverCloudKvMaterial` و`rejectCalendarCloudKv` لم يُمسّا. الخادم ما زال أعمى — لا كلمة `calendar` في المسار |
| توافق | نقطة v1 قديمة بلا حقل تقويم: `calendarSlicePresent: false` — ليست تفريغاً متعمّداً |
| onlyIfLocalEmpty | يفحص الإضابير فقط — تقويم محلي لا يمنع سحب الدعاوى |
| عزل الفشل | كل شريحة تُطبَّق وحدها؛ فشل التقويم أو الدعاوى لا يلغي الباقي |
| مزامنة كل شيء | تنتظر الدفع؛ تستخدم `WorkCloudCheckpointPushResult` لا نوعاً بنيوياً مرتجلاً |
| سلال | الرفع لا يضم دعاوى/تنفيذ/ملاحظات إن سلتها مطفأة. `hasLocalWorkDossiers` يقرأ الجهاز بلا سلال |
| ترحيل الشرائح | شريحة سلّتها مطفأة تُنقل من **أحدث** نقطة سابقة فقط (`latest`) — لا فك لثلاثة صفوف على الدفع |
| تعذّر قراءة السابقة | عطل نقل عند القراءة يُرجع `failed` + `retryable`. نقطة موجودة لا تُفكّ = بلا قيمة، فيُسمح بالكتابة |
| توقيع | فك النقطة مرفوض بلا `data_signature` |
| تقويم بلا سلال | `cloudSync` كافٍ لرفع شريحة التقويم المشفّرة |
| تفعيل المزامنة | ينتظر الاستعادة؛ `failed` على GET/فك يستخدم التحذير القائم |
| دفع مؤجّل | محاولة ثانية **فقط** إن `retryable` (نقل). فشل الحجم لا يُعاد |
| مفتاح التخزين | `CALENDAR_EVENTS_STORAGE_KEY` — لا نص حرفي في نقطة العمل |
| سقوط جمع الدعاوى | `loadLocalLawsuits` يقرأ المخزن إن رمى `collectLawsuitLocalRowsForSync` |

ملفات: `workCloudCheckpointCalendar.ts`، `workCloudCheckpoint.ts`، `workCloudCheckpointHistory.ts`، `workCheckpointRetention.ts`، `calendarTombstones.ts`، `runCloudSyncAllNow.ts`، `dataCloudSyncToggle.ts`، `src/app/api/work-checkpoints/route.ts`، `supabase/migrations/20260830160000_lawyer_work_checkpoints_keep_anchor.sql`.

## الحدود (ما توقّفنا عنده ولماذا)

| الحد | السبب |
|------|--------|
| الدفع المؤجّل بلا توست بعد إعادة المحاولة | ليس مسار «مزامنة كل شيء»؛ لا رسالة جديدة |
| لا مسار مستقل للمعاملات/المخزن داخل الحزمة | KV مختوم خلف بوابة العمل — ليست ثغرة تقويم |
| الاستعادة دمج لا لقطة مطابقة | موعد أحدث على الجهاز يبقى |
| `keep_anchor` خارج التشفير | الخادم أعمى؛ العلم يقول «حزمة مكتملة» لا محتوى. بدونه لا تُحمى الشريحة من التقليم |
| ثنائي Capacitor غير محدَّث | يقرأ `checkpoint` الأحدث فقط. هذا البناء يملأ `checkpoints[]` بالمرساة. لا يمكن ترقيع APK نُشر سابقاً من المستودع |
| `tsc` المستودع | ~1192 خطأ خارج الشريحة |
| قياس هاتف / pentest على إنتاج حي | لا جهاز ولا صلاحية حساب محامٍ حي في هذه الجلسة |

## الموقع

**جاهز للانتقال: نعم** ضمن الحدود. المواعيد تدخل المزامنة الشاملة مشفّرة مع نقطة العمل. KV للتقويم ما زال مرفوضاً. WIFE يبقى على طلب `/api/work-checkpoints` فقط، لا على كل حفظ يومي.

## المصداقية — ما لم يُنفَّذ

- لا حملة `test:e2e:wife:full`، لا Redis إنتاج، لا جهاز Android/iOS متصل.
- الخادم لا يزال أعمى عن محتوى النقطة؛ لم نُثبت ذلك على حساب محامٍ حي.
- `KEEP_LATEST` بقي 3 **مع** مرساة مكتملة لا تُقلَّم. لم نرفع النافذة بلا حد.
