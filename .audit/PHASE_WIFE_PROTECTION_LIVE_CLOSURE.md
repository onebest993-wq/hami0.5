# إغلاق — حماية WIFE بعد الاختبار الحي

**التاريخ:** ٢١ آب ٢٠٢٦  
**النطاق:** توقيع الطلبات (WIFE) فقط — ليس قطع الاتصال / local-only.

---

## ما أُنجز

### إصلاحات منتَج

1. **توكن التوقيع قبل اكتمال `getSession`**  
   `getCurrentAccessToken` يقرأ JWT المخزَّن، ثم `hami:dev-mock-access-token`، ثم جلسة الشِل/الضيف عند فتح الواجهة محلياً.  
   ملفات: `src/app/services/auth/localSigningToken.ts`، `src/app/services/SecureAPIClient.ts`.

2. **توقف 401 لا يلغي التوقيع على السلك**  
   `fetchSecure` بعد 401 يتوقف ٣٠ ثانية (منع عاصفة JSON). الحارس و`fetchSecureResponse` يبقيان يوقّعان إن وُجد توكن.  
   ملف: `src/app/services/secureApiWifeSigning.ts`.

3. **مسبار الصحة** (سابق في الحملة): الشِل المفتوح لا يعلّم الـ API غير متاح قبل `healthz`.

## التقييم (صادق)

| البُعد | درجة | ملاحظة |
|--------|------|--------|
| أداء | جيد | ٣٠ اختبار متصفح في ~٤٩ ث؛ الاندفاع ٥ طلبات تحت ١٠ ث |
| نظافة | جيد | وحدة توكن واحدة؛ لا دمج HMAC العميل مع BFF |
| أمان | جيد مع سقوف بروتوكول | الرفض غير الموقّع حيّ؛ التوقيع من المتصفح مُبرهَن |
| جودة كود | جيد | فصل pause عن وجود التوكن |
| موبايل | غير ممسوس بصرياً | الحارس على `fetch`؛ Capacitor يرث نفس المسار |

## الحدود (ليست «لاحقاً داخل WIFE»)

- لا JWT محامٍ إنتاجي ضد Supabase حيّ — لا إثبات round-trip 200 لحساب حقيقي.
- HMAC من JWT (`:wife-sign-v1`) سقف بروتوكول، ليس سراً ثانياً.
- معرّف الجهاز من العميل؛ CSRF يُتخطى على GET/HEAD/OPTIONS.
- WIFE يغلف `fetch` لا `XMLHttpRequest`.
- `/api/security/wife-sign` أوراكل توقيع allowlisted لنفس الأصل.
