# إغلاق مرحلة: Auth — بوابة الدخول وتسجيل المحامي (جولة أولى)

**التاريخ:** ١١ آب ٢٠٢٦  
**النطاق:** بوابة الإنتاج، ضيف محلي صريح، تسجيل محامٍ متعدد الخطوات، حالة `pending`، حراسة الشبكة للمنتدى  
**الإنتاج المستهدف:** BFF (`VITE_BFF_AUTH=true`) + signup عبر Supabase ثم login BFF

---

## ما أُنجز

| عنصر | تفاصيل |
|------|--------|
| بوابة اختيار | `LawyerAuthGate`: دخول / إنشاء حساب / بدون تسجيل |
| دخول | `LawyerSignInForm` (نفس مسار `login` BFF/Supabase) |
| ضيف صريح | `enterLocalGuest` + `hami:auth:explicit-local-guest:v1` — ليس `VITE_SHELL_AUTH_OPEN` |
| تسجيل | بيانات + بطاقة هوية + وجه اختياري → `authRegisterLawyer` → حالة `pending` |
| حراسة شبكة | `canUseNetworkFeatures` — الحسابات القديمة بلا سجل تبقى `active` |
| منتدى | فتح المنتدى يمر عبر `canUseNetworkFeatures` + رسائل pending/guest |
| شريط حالة | `LawyerVerificationStatusBanner` داخل الـ shell |
| اختبارات | 23 ناجحة (account status + shellAuth + authBoot + community) |

---

## الحدود / ما لم يُنفَّذ بعد

1. **مطابقة وجه↔هوية** — غير موصولة؛ الخطوة اختيارية لحفظ السيلفي فقط + مراجعة بشرية لاحقاً  
2. **لوحة اعتماد إدارية** — `setLawyerVerificationStatus` موجود؛ لا UI إدارة  
3. **رفع وثائق مشفّر إلى الخادم** — التخزين محلي حالياً (قد يُحذف عند مسح البيانات)  
4. **BFF `/api/auth/signup`** — التسجيل عبر عميل Supabase ثم `bffLogin`  
5. **تعميم `canUseNetworkFeatures`** — المنتدى مُحدَّث؛ باقي الميزات الشبكية ما زال كثيرها على `isRealSignedIn` فقط  
6. **استعادة كلمة المرور** — لم تُبنَ في هذه الجولة  
7. **E2E إنتاجي** (`SHELL_AUTH_OPEN=false` + تسجيل حقيقي) — لم يُشغَّل  
8. **تأكيد بريد Supabase** — إن فُعّل، قد يفشل الدخول التلقائي بعد signup (رسالة خطأ صريحة)

## قرار المنتج المثبّت

بعد إتمام التسجيل يدخل المحامي التطبيق فوراً كـ **`pending`** (وضع محلي عملياً للميزات الشبكية)، مع Toast يوضح انتظار التدقيق — وليس شاشة انتظار مغلقة.
