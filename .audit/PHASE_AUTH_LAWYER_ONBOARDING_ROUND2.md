## ما أُكمل في هذه الجولة

| نقص سابق | الحالة |
|----------|--------|
| تعميم حراسة الشبكة | مزامنة سحابية + إشعارات خلفية + دوك المنتدى + رفض منتدى خادمي لـ pending |
| استعادة كلمة المرور | `POST /api/auth/forgot-password` + زر في شاشة الدخول |
| BFF signup | `POST /api/auth/signup` + `bffSignup` + تسجيل عبر BFF |
| مساعد هوية OCR | `lawyerIdentityAssist` — إشارة محلية فقط إن وُجد نص |
| وجهي | فحص حضور السيلفي بصدق — **ليس** مطابقة بيومترية |
| طابور اعتماد | `POST/GET/PATCH /api/auth/lawyer-verification` + تبويب إدارة حي |
| رفع طلب للخادم | بعد التسجيل → KV `lawyer-verification:{userId}` |

## التقييم

| البُعد | درجة | ملاحظة |
|--------|------|--------|
| أداء | 8 | OCR اختياري عند خطوة الهوية |
| نظافة | 8.5 | مسارات API منفصلة + remote client |
| أمان | 8 | rate limit على signup/forgot؛ المنتدى يرفض pending على الخادم |
| جودة | 8.5 | فصل واضح guest / pending / active |
| موبايل | 8 | لم يتغير شكل الهوية العامة |
| صدق | 9.5 | مطابقة وجه↔هوية آلية غير موجودة؛ E2E إنتاجي لم يُشغَّل |

**جاهز للانتقال؟** نعم لقسم آخر — مع الحدود أدناه.

---

## حدود ما زالت قائمة

1. مطابقة وجه بيومترية حقيقية (Face API) — غير منفَّذة عمداً  
2. صور الهوية الكاملة على الخادم محدودة بمعاينة مختصرة  
3. اعتماد الإدارة يعتمد على KV + صلاحية admin؛ بدون KV يظهر تبويب فارغ  
4. E2E بـ `VITE_SHELL_AUTH_OPEN=false` لم يُشغَّل في هذه الجولة  
5. بعض الميزات المحلية ما زالت على `isRealSignedIn` فقط (مقصود للوضع المحلي أثناء pending)
