# تصميم واجهات: محضر المتابعة + نافذة المتابعة (ملء الشاشة)

## 1) إرشادات عامة (Desktop-first)
### Layout
- اعتماد Flexbox بتخطيط RTL افتراضي داخل نطاق “محضر المتابعة” وداخل نافذة المتابعة.
- نقاط توقف مقترحة: Desktop ≥ 1280px (الافتراضي)، Tablet 768–1279px، Mobile < 768px.

### Meta Information
- Title: محضر المتابعة
- Description: إدارة ومتابعة إجراءات الملف مع واجهة منظمة.
- OpenGraph: عنوان/وصف مطابقين (بدون متطلبات مشاركة إضافية).

### Global Styles (Design Tokens مقترحة)
- اتجاه: `dir="rtl"`.
- ألوان: خلفية حيادية فاتحة (#F7F7F8)، سطح بطاقات أبيض (#FFFFFF)، لون أساسي (Primary) حسب هوية النظام الحالية.
- Typo: خط عربي واضح، أحجام 14/16/18/22.
- أزرار: Primary (ممتلئ) + Secondary (حدود) + Disabled state واضح.
- Hover/Focus: ظل خفيف + إطار تركيز (focus ring) واضح لدعم لوحة المفاتيح.

## 2) صفحة/قسم: محضر المتابعة
### Page Structure
- هيكل مكدّس (Stacked):
  1) Header عنوان الصفحة + معلومات مختصرة (إن وجدت حالياً).
  2) شريط إجراءات موحد (تم نقل الأزرار إليه).
  3) منطقة التبويبات + محتوى التبويب.

### Sections & Components
1. **Header**
   - عنوان: “محضر المتابعة”.
   - (اختياري حسب الموجود) شارة حالة/رقم ملف.

2. **Action Bar (شريط الإجراءات الموحد)**
   - الموقع: أسفل الهيدر مباشرة، بعرض كامل، Sticky أعلى منطقة المحتوى عند التمرير.
   - المحتوى: نفس أزرار الإجراءات الحالية بعد نقلها (بدون إضافة أزرار جديدة).
   - محاذاة RTL: الأزرار الأساسية تبدأ من اليمين إلى اليسار.
   - حالات الأزرار:
     - Loading: إظهار مؤشر تحميل على الزر فقط.
     - Disabled: إظهار سبب مختصر عند التعطيل (Tooltip/Helper text) خصوصاً لزر “تفعيل الطلب”.

3. **Tabs (تبويبات المحضر)**
   - إزالة تبويب “الصرف/Disburse” بالكامل.
   - إبقاء بقية التبويبات كما هي مع تمييز التبويب النشط.
   - شريط تبويبات أفقي (كما هو غالباً) مع قابلية التمرير عند ضيق العرض.

4. **Approved Request Activation (تفعيل الطلب المعتمد)**
   - عندما تكون حالة الطلب “Approved/معتمد”: زر/إجراء “تفعيل الطلب” يكون Enabled.
   - عندما لا تكون “Approved”: زر Disabled مع نص سبب (مثال: “لا يمكن التفعيل قبل الاعتماد”).

## 3) نافذة المتابعة (ملء الشاشة) مع تبويبات عمودية RTL
### Page Structure
- Overlay ملء الشاشة يغطي التطبيق.
- تخطيط عمودين (RTL):
  - يمين: قائمة تبويبات عمودية.
  - يسار: محتوى التبويب (النموذج/التفاصيل).

### Sections & Components
1. **Modal Shell (إطار النافذة)**
   - Header علوي: عنوان (مثلاً “متابعة”) + زر إغلاق واضح.
   - Body: منطقة المحتوى (التبويبات + المحتوى).
   - Footer ثابت (Sticky): أزرار حفظ/إلغاء (أو ما يعادلها حالياً) مع أولوية واضحة.
   - سلوك: منع تمرير الخلفية، إغلاق عبر Esc، تأكيد قبل الإغلاق عند وجود تغييرات غير محفوظة (إن كان هذا موجوداً حالياً؛ وإلا يتم تجاهله).

2. **Vertical Tabs (RTL)**
   - عرض ثابت للقائمة اليمنى (مثلاً 240px على الديسكتوب).
   - عناصر التبويب: Label عربي + (اختياري) أيقونة صغيرة.
   - حالات:
     - Active: خلفية مميزة + خط أثقل.
     - Hover: تمييز خفيف.
     - Focus: إطار تركيز واضح.
   - على الشاشات الأصغر: تتحول القائمة إلى شريط تبويبات أفقي أعلى المحتوى أو Dropdown (حسب مكتبة UI الحالية).

3. **Tab Content / Follow-up Form**
   - المحتوى يظهر ضمن Card/Panel أبيض مع padding مناسب.
   - الحقول (كما هي حالياً) مرتبة عمودياً مع مجموعات واضحة.
   - التحقق: رسائل خطأ تحت الحقل مباشرة، مختصرة وبالعربية.
